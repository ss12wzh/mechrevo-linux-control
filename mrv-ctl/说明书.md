# mrv-ctl 使用说明书（v3.3）

适用对象：在 Ubuntu 上使用机械革命 Uniwill 准系统游戏本、想恢复性能档 / 风扇 / 键盘灯 / 限充的用户。  
当前版本：3.3.1（deb：`mrv-ctl_3.3.1_all.deb`）。  
验证机型：机械革命苍龙系列（`CANGLONG Series-M6DR55xx`，Ryzen 9 8945HX + RTX 5060 Laptop，BIOS `N.1.16MRO13`，Ubuntu 24.04，内核 7.0 HWE，NVIDIA 595）。

---

## 1. 结论先看

| 问题 | 答案 |
|---|---|
| 40/50 系机械革命新机器能直接装上就用吗？ | **不能当成「全系列开箱即用」。** 同代 Uniwill 准系统有机会装上并能探测到功能，但寄存器、功耗墙数值、风扇能力都按机型而变。目前只有苍龙 5060 这一台经过完整实测。 |
| Linux 下独显能到 Windows 那种 140W 吗？ | **目前不能。** 本机狂暴档 + nvidia-powerd 实测 GPU 生效上限 **115W**（OEM 标称上限）。140W 是 Windows 上 NvpwrControl 改 NVIDIA 驱动内部对象的实验档，Linux 没有对等入口。 |
| 现在能做什么？ | 修复 Ubuntu 独显锁 50W（恢复到 OEM 115W）、三档性能模式（CPU 实测约 45 / 87 / 130W）、风扇强冷、高温自动强冷、键盘 RGB、电池限充、Mux 查询/切换（需重启）。 |

## 2. 安装

### 2.1 系统要求

- Ubuntu 24.04（或同代 Debian/Ubuntu 衍生版）
- 已安装 NVIDIA 闭源驱动（本机为 595；570/550 一类官方包一般也可）
- 内核带 `uniwill_laptop`（Ubuntu 6.12+ / 本机 7.0 已有）。非 TUXEDO 品牌需 `force=1`，安装脚本会写好
- `acpi-call-dkms`（deb 依赖会拉）

不要同时跑 **TUXEDO Control Center / tccd**：会和本程序抢 CPU 策略和性能档。本机实测 TCC 风扇 API 也不可用。

### 2.2 安装步骤

在源码目录：

```bash
sudo ./install.sh
```

这会构建 `dist/mrv-ctl_<版本>_all.deb` 并 `apt` 安装。也可以只装现成 deb：

```bash
sudo apt-get install -y ./dist/mrv-ctl_3.3.1_all.deb
```

安装脚本会：加载 `acpi_call` 与 `uniwill_laptop force=1`、写开机自动加载、启用 `mrvd` 守护进程、补 Ubuntu 常缺的 `nvidia-powerd` unit 与 D-Bus 策略、安装桌面入口与托盘自启动。

**一般不需要重启。** 显卡模式（Mux）切换例外，固件要求重启才完成输出切换。

### 2.3 启动与命令

- 图形界面：应用菜单里的「mrv-ctl」，或 `/usr/bin/mrv-gui`（普通用户即可）
- 命令行：

```bash
mrvctl status                     # 整机状态 + 平台参数
mrvctl profile office|balanced|boost
mrvctl fan boost                  # 强冷（EC 全速）
mrvctl fan auto                   # 交还 EC 固件曲线
mrvctl fan guard on 88 78         # 高温自动强冷
mrvctl kbd 150
mrvctl kbd color 185 40 46
mrvctl kbd effect solid|rainbow|off
mrvctl charge 80
mrvctl mux query
# Mux 切换会下电/上电独显并需要重启：
# mrvctl mux dgpu|standard --yes
```

写操作需要本机 `sudo` / `admin` / `wheel` / `mrv` 组成员（当前登录用户一般在 sudo 组里即可）。

### 2.4 卸载

```bash
sudo apt-get remove mrv-ctl
# 或彻底清除配置：
sudo apt-get purge mrv-ctl
```

## 3. 新机器能不能「直接安装生效」

### 3.1 为什么不能保证全系列

机械革命 40/50 系游戏本多数是 **Uniwill 准系统**，硬件通道（EC `ECRR/ECRW`、WMI `WKBC`、NVPCF）往往存在，所以 **deb 多半能装上、守护进程能起来、界面能开**。  
但「生效」取决于固件：

1. **性能档寄存器** 本机是 `0x0751`（静音 `0xA0` / 平衡 `0x00` / 狂暴 `0x10`）。无界等轻薄本曾用过 `0x7A6`，不能照搬。
2. **CPU 功耗墙** 非自定义模式下 `0x0783/0x0784` 读出来是 0，固件内部锁死。界面上的「约 45/87/130W」是 **苍龙 M6DR55 实测值**，写在 `MEASURED_CPU_PPT` 里，换机型必须重测。
3. **风扇** 本机不支持 16 点自定义曲线；只支持 `0x0751` bit6 全速强冷。别的 40/50 机型可能相反。
4. **内核接口** 依赖 `uniwill_laptop` 的 sysfs（键盘灯、温度、转速）。机型不在白名单时靠 `force=1`，部分功能可能缺失。
5. **nvidia-powerd** 依赖 SBIOS 上报 Dynamic Boost。没有 NVPCF 就解不开 50W 锁。

启动时 `mrvd` 会探测能力（性能档 / 限充 / 风扇 / RGB / Mux 等），界面按探测结果隐藏不支持的区块。**探测通过 ≠ 功耗墙数值正确。**

### 3.2 新机建议流程（不重启也能做）

1. 确认是 Uniwill：`ls /sys/devices/platform/INOU0000:00` 存在。
2. 安装 deb，看 `systemctl status mrvd` 与 `mrvctl status`。
3. 只读探测：`sudo scripts/probe-readonly.sh`（结果对照苍龙的 `docs/probe/probe-before.txt`）。
4. 切三档，用 `nvidia-smi -q -d POWER` 和 CPU 满载看功耗是否明显分档。
5. 不要先开 Mux 切换、不要先写未知 EC 地址。

若 `0x0751` 读写失败或三档功耗几乎一样，说明本机协议不同，需要按该机 DSDT 再适配，而不是「装完就能当苍龙用」。

### 3.3 目前验证过 / 未验证

| | 状态 |
|---|---|
| 苍龙 M6DR55 + RTX 5060 Laptop | 完整实测（性能档、强冷、灯、限充、nvidia-powerd 115W） |
| 同代 Uniwill + 40/50 系 NVIDIA | **未众测。** 安装可能成功，功能需逐项确认 |
| Intel 平台 / 非 Uniwill / 无独显 | 超出范围 |

## 4. 现在实际能到的功耗

苍龙 5060 Laptop，狂暴档 + nvidia-powerd：

| | 静音 | 平衡 | 狂暴 |
|---|---|---|---|
| CPU 满载稳态（实测） | ≈45 W | ≈87 W | ≈123–130 W（97°C 会掉） |
| GPU 负载下生效上限 | 105 W | 85 W | **115 W** |
| GPU 负载功耗（4K 离屏 glmark2） | ≈91 W | ≈84 W | ≈94 W |

说明：

- Ubuntu 刚装完常见现象是独显锁在 **50W**。装本程序并启用 nvidia-powerd 后，上限回到 OEM **115W**。
- 静音档 GPU 上限（105W）可以高于平衡档（85W）：两档平台总预算（TPP）都是 55W 量级，静音把 CPU 压低后 Dynamic Boost 把额度分给 GPU。玩游戏若还想安静，需要另压 GPU/TPP，目前没做。
- `nvidia-smi -pl` 在笔记本上会被驱动拒绝。

## 5. Windows 为什么能到 140W

Windows 上常见两条完全不同的路：

### 5.1 官方 / L-Mechrevo：OEM 契约内（到 115W 这一档）

L-Mechrevo 通过机器上的 **GCU 服务** 切性能档、设 CPU PL1/PL2/PL4、设 GPU TGP 目标和 Dynamic Boost。  
对 5050/5060/5070 Laptop，OEM 设计上限就是 **115W 基础 TGP + Dynamic Boost**，不是 140W。

Linux 没有 GCU。本程序绕开 GCU，直接写 EC 性能档 + 启用 nvidia-powerd，对应的是这一档，不是超规格档。

### 5.2 NvpwrControl：改驱动内部对象（120–140W，实验性质）

`NvpwrControl`（你下载目录里的 4090mod）对 5050/5060/5070 Laptop 菜单是 **OEM 115W + 实验档 120–140W**。做法是：

- 自写内核驱动 `Nvpwr.sys`，在运行时改 **nvlddmkm.sys 内核对象**（功耗策略、上限字段等）
- 绑定特定 NVIDIA 驱动版本（文档写 616.92）
- 需要关 Secure Boot、开 Windows 测试签名，或正规签名
- 项目自己把 120–140W 标成 **experimental**；275W 明确不做

也就是说：**140W 不是 BIOS/EC 对 5060 Laptop 承诺的档位**，而是软件改了 NVIDIA 驱动内部的功率策略。  
Linux 的 `nvidia.ko` 没有公开、稳定、对等的「改内核功耗对象」接口；`nvidia-smi -pl` 在笔记本上被封；EC 的 CTGP 偏移（`0x0744` 等）本机写过，NVML 上限仍停在 115W（被 NVPCF 协商压住）。

因此：Windows 能到 140W，是因为有人做了针对 Windows 驱动的私有补丁路径；不是机械革命官方 Linux 缺一个开关。

## 6. Linux 上若要做「超过 115W」该怎么做

按风险从低到高，建议只走官方/固件通道；**不要移植 Nvpwr.sys 那种改驱动内存的做法**（驱动一升级就失效，且没有 Linux 安全等价物）。

### 6.1 先保证已经吃满 OEM 115W（已做）

1. 狂暴档（EC `0x0751` bit4）  
2. `nvidia-powerd` 在跑（NVPCF / Dynamic Boost）  
3. 用足够重的 GPU 负载验证（4K 离屏或真实 3D），不要用 14W 的轻负载下结论  

本机这一段已经验证。

### 6.2 值得继续试的固件通道（未完成，有机会但无保证）

这些都不改 NVIDIA 内核对象，失败了可以回滚：

1. **自定义功耗模式**  
   EC `0x0727` bit6（DSDT 里的 `CUME`）打开后，才允许写 `0x0783/0x0784/0x0785`（APL1/APL2/APL4）。L-Mechrevo 更新日志也写过：不先切自定义模式，功耗墙写入会失败。  
   这主要动 **CPU PPT**，GPU 未必突破 115W。

2. **CTGP / TPP / DB 偏移走驱动 sysfs**  
   本机已有 `/sys/devices/platform/INOU0000:00/ctgp_offset`。以前直写 EC `0x0744` 无效，是因为没让 NVPCF 重新协商。应：改 sysfs → 等 powerd 重协商 → 重负载看 `enforced.power.limit`。  
   仍可能被 SBIOS 的 Max 115W 卡住。

3. **TPP 偏移（`0x0745`）**  
   默认 `0xFF`（不限）。若要「静音档连 GPU 一起压」或反过来抬平台预算，可以单独做受控实验。抬预算也不等于 NVIDIA 驱动承认 >115W。

4. **对照 Windows 在双系统下读 EC**  
   在 Windows 用官方控制台或 L-Mechrevo 切到「自定义 / 140W 若来自 GCU」后，不关机进 Linux 只读 EC（`0x0751/0x0727/0x0743–0x0746/0x0783–0x0788/0x07D5/0x07F7`）。  
   若 Linux 读到的上限仍是 115W，即可确认 140W **只存在于 Windows 驱动对象里**，不在 EC。

### 6.3 不建议做的

| 做法 | 原因 |
|---|---|
| 把 Nvpwr.sys 的偏移搬到 `nvidia.ko` | 每版驱动符号/布局都变；无公开契约；签名与安全启动冲突 |
| 通用 EC 写工具给最终用户 | 写错风扇相关寄存器会停转 |
| 宣称 40/50 系全都能 140W | 即使 Windows 上也是实验档，且因 GPU 而异（5070 Ti 起菜单就不是 140W 这条线） |

### 6.4 若一定要追 140W 的工程顺序

1. 双系统对照：Windows 140W 时 EC 快照 vs Linux 115W 时 EC 快照。  
2. 若 EC 有差异 → 在 Linux 用 WKBC 复现同一组寄存器，并触发 `PMSF`/`PWUP` 让 NVPCF 刷新。  
3. 若 EC 无差异 → Linux 侧没有固件开关，只能：等 NVIDIA 官方开放笔记本功耗帽，或放弃超 OEM。  
4. 任何写入实验：基线存盘、看门狗超时恢复、只往更凉/已验证地址写、全程记录 `nvidia-smi -q -d POWER`。

**当前项目定位：把 Linux 用到 OEM 设计点（5060 Laptop = 115W），不承诺 140W。**

## 7. 界面与日常使用

- **概览**：GPU 功耗大数字、CPU/GPU/风扇/电池；CPU 条按本机实测功耗墙比例着色。  
- **控制**：风扇自动/强冷、高温自动强冷、显卡模式、限充、键盘灯、Fn 锁等。  
- **悬浮窗**：CPU/GPU 温度与 GPU 功耗；拖动、双击开关主窗口。  
- 窗口位置等保存在 `~/.config/mrv-ctl/gui.json`。

安全相关：EC 只写白名单地址；写入优先走 `WKBC` 命令通道；风扇强冷与性能档共用 `0x0751` 的不同位，互不覆盖。不要手动 `systemctl restart dbus`（会踢掉图形会话）。

## 8. 排错

| 现象 | 处理 |
|---|---|
| `mrvctl` 提示 mrvd 未运行 | `systemctl status mrvd`；确认 `/proc/acpi/call` 存在（`acpi-call-dkms`） |
| 独显仍 50W | `systemctl status nvidia-powerd`；`nvidia-smi -q -d POWER`；确认已装 NVIDIA 驱动 |
| 切档 CPU 功耗不变 | 用满载测（不要看空闲）；对照 `mrvctl status` 里的平台参数；可能不是苍龙这套 `0x0751` |
| 风扇曲线没有 | 本机固件不支持，只用强冷 |
| 和 TCC 抢设置 | 卸掉 `tuxedo-control-center` |
| GUI 起不来 | 依赖 `python3-gi`、`gir1.2-gtk-3.0`、托盘可选 `gir1.2-ayatanaappindicator3` |

诊断打包可参考仓库里的探测日志：`docs/probe/`、性能数据 `docs/perf/`。

## 9. 免责

改 EC / 功耗 / 风扇有稳定性与硬件风险，本程序按现状提供。超 OEM 的 TGP（120–140W）在 Windows 上也是实验功能；Linux 侧尚未具备同等能力，请勿在生产环境假设「装完等于满血 140W」。
